План виправлення перекладу новин:

1. Перебудувати логіку перекладу в backend-функції новин
- Прибрати масове паралельне звернення до безкоштовного fallback-перекладача, бо в логах видно серію `429` — сервіс блокує часті запити.
- Зробити основним шляхом переклад через наявний `GEMINI_API_KEY`.
- Перекладати новини малими контрольованими батчами, з паузами, retry/backoff і чітким результатом: скільки реально перекладено, скільки пропущено, чому.

2. Зробити переклад передбачуваним для користувача
- Кнопка «Перекласти» буде перекладати видимі неперекладені новини послідовно, без фальшивого успіху.
- Якщо ліміт API тимчасово вичерпаний — показувати нормальне повідомлення, а не нескінченний стан «перекладається».
- Після успішного перекладу одразу оновлювати список, щоб користувач бачив український текст без ручного перезавантаження.

3. Додати стабільний fallback без спаму
- Fallback-переклад лишити тільки як резерв для одиничних текстів, з дуже малим лімітом і паузами.
- Не запускати fallback масово для десятків новин — це і є причина нестабільності.

4. Покращити клієнтський UX у розділі «Новини»
- Додати зрозумілий стан перекладу: «перекладаємо N новин…».
- Кнопку блокувати на час процесу.
- При частковому успіху показувати чесний результат, наприклад: «Перекладено 12 з 20».
- При помилці не ламати стрічку: лишати оригінал і давати повторити.

5. Перевірка
- Перевірити виклик ручного перекладу на реальних новинах.
- Перевірити оновлення стрічки після перекладу.
- Перевірити, що більше немає масових `429` від fallback-перекладача.
- Задеплоїти оновлену backend-функцію новин.
